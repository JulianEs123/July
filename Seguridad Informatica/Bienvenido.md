### 2.1 Definiciones Básicas

Amenaza:  
Es cualquier circunstancia o evento que puede explotar una vulnerabilidad para causar daño a los sistemas, datos o recursos de una organización. Las amenazas pueden ser tanto externas (cibercriminales) como internas (empleados o usuarios malintencionados).

Vulnerabilidad:  
Es una debilidad o fallo en un sistema, aplicación o red que puede ser aprovechada por un atacante para comprometer la seguridad del mismo. Las vulnerabilidades pueden incluir errores de programación, configuraciones incorrectas o falta de actualizaciones.

Riesgo:  
Es la posibilidad de que una amenaza explote una vulnerabilidad, causando un daño o pérdida significativa para una organización. El riesgo se calcula en función de la probabilidad de que un ataque ocurra y el impacto que tendrá si se materializa.

Caja Negra, Caja Blanca y Caja Gris:  
Estos términos se utilizan en el contexto de las pruebas de seguridad para describir el conocimiento del sistema por parte del atacante durante un test de penetración.

- Caja Negra: El atacante no tiene conocimiento previo del sistema o la red, y debe intentar penetrar sin ninguna información interna.
    
- Caja Blanca: El atacante tiene un conocimiento completo del sistema o red, incluyendo acceso al código fuente, configuraciones, etc.
    
- Caja Gris: El atacante tiene algo de conocimiento del sistema, pero no tiene acceso completo. Es un término intermedio entre la caja blanca y la caja negra.
    

  

### 2.2 Tipos de Análisis de Seguridad

Ethical Hacking:  
Es la práctica de realizar pruebas de penetración con el permiso de la organización, para encontrar vulnerabilidades y resolverlas antes de que los atacantes malintencionados las exploten.

Penetration Testing (Pentesting):  
Se refiere a un conjunto de pruebas diseñadas para evaluar la seguridad de un sistema al simular un ciberataque real. Esto incluye el uso de herramientas y técnicas para detectar debilidades.

Red Teaming:  
Es una simulación de ataque más avanzada en la que un equipo actúa como un adversario para evaluar la capacidad de respuesta y las defensas de una organización frente a ataques complejos y prolongados.

Análisis de Vulnerabilidades:  
Es el proceso de escanear y evaluar los sistemas en busca de debilidades que los atacantes puedan explotar. Esto se realiza utilizando herramientas automatizadas o manualmente.

Auditoría de Seguridad:  
Es una evaluación exhaustiva de las políticas, procesos y controles de seguridad de una organización. Su objetivo es verificar si los sistemas y redes cumplen con los estándares de seguridad y normativas aplicables.

  

### 2.3 Tipos de Pentesting

El Pentesting puede realizarse en diferentes áreas, dependiendo de las necesidades y los puntos críticos de seguridad de una organización:

1. Network Pentesting:  
    Evaluación de la seguridad de las redes y su infraestructura.  
      
    
2. Client-Side Pentesting:  
    Pruebas en aplicaciones de cliente, como navegadores, aplicaciones móviles y programas de escritorio.  
      
    
3. Web Pentesting:  
    Evaluación de la seguridad en aplicaciones web y sus vulnerabilidades, como inyecciones SQL o XSS.  
      
    
4. Wireless Pentesting:  
    Evaluación de la seguridad de las redes inalámbricas, incluyendo la configuración de routers y la autenticación de la red.  
      
    
5. Ingeniería Social:  
    Evaluación de la capacidad de los empleados de una organización para resistir ataques que intentan manipularlos, como phishing o vishing.  
      
    
6. Pentesting Físico:  
    Pruebas de seguridad que buscan evaluar la protección física de los sistemas, como el acceso no autorizado a las instalaciones o equipos.  
      
    

### 2.4 Metodologías

Para realizar un Pentest eficaz, es fundamental seguir metodologías estructuradas. Algunas de las más reconocidas incluyen:

Penetration Testing Execution Standard (PTES):  
Un conjunto de prácticas estandarizadas para realizar pruebas de penetración, que cubren desde la planificación hasta la ejecución y presentación de los resultados.

OWASP Testing Guide:  
Una guía creada por la Open Web Application Security Project (OWASP), que proporciona metodologías detalladas para probar la seguridad de las aplicaciones web.

  
  

### 2.5 Fases de un Pentest

Un test de penetración se divide generalmente en tres fases clave:

1. Fase de Preparación:  
    Se lleva a cabo la planificación, recopilación de información y definición de los objetivos del pentest. Esto incluye identificar los sistemas a probar y obtener el permiso adecuado.  
      
    
2. Fase de Ejecución:  
    Es la fase donde el pentester intenta explotar las vulnerabilidades encontradas para verificar si pueden ser aprovechadas, utilizando técnicas de hacking ético.  
      
    
3. Fase de Presentación de Resultados:  
    En esta fase se documentan los hallazgos, se generan informes detallados y se presentan los resultados a la organización. El informe incluye recomendaciones para mitigar las vulnerabilidades.  
      
    

### Resumen Ejecutivo

El resumen ejecutivo es una parte clave del informe, que presenta los resultados y conclusiones de forma clara y accesible para la alta dirección.

- Introducción: Descripción del objetivo del pentest y el alcance.
    
- Metodología Seguida: Explicación del enfoque utilizado durante el análisis.
    
- Vulnerabilidades Encontradas: Listado de las debilidades descubiertas.
    
- Conclusiones: Reflexión sobre el nivel de seguridad y las recomendaciones.
    
- Anexos: Datos técnicos adicionales, como capturas de pantalla, registros de pruebas, etc
